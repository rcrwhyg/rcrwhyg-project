# 个人站风格与信息架构：从"主题伪装"到"设计语言"

> **摘要**: 这是一次站点重塑的设计笔记。起因是我先后试过"像素游戏机"和"命令行终端"两种风格来做个人站——结果都显得割裂：访客是来看内容的，却被要求先进入一个剧本。本文按发生顺序记录这次重设：为什么会割裂、调研看了什么、最后为什么选了"薄荷绿 + 天空蓝 + 阴影 + 光 + 玻璃"这套统一设计语言，以及由此推导出的信息架构（学习雷达 / 实验室 / 枢纽首页 / 统一文章系统）。读完后你会知道：一个站的"个性"不来自"换一层主题皮肤"，而来自设计语言本身。

## 起因：为什么这次重设

之前的版本有两套并行的文章系统（`/blog` 是后台管理的 DB 表，`/articles` 是文件式的 git+CD 流水线），导航也只到"博客+工具"两个内容板块。在写完《从零重建到一键部署：一条 CD 流水线的诞生》后，我意识到：CD 把发布流程做对了，但站点**作为一个产品**——信息架构、视觉系统、内容深度——都还停在"能跑就行"。我前后也做过两次大胆尝试：

- **像素游戏机风格**：单色 + 方块拼贴 + 极强对比。看起来很"有性格"，但看文章正文时眼睛很累。
- **命令行终端风格**：黑底 + 绿色高亮 + 类 shell 装饰。开发者友好，但常规访客觉得"不伦不类"。

两种风格都不是"站得稳"的设计。它们更像是**在内容上面套了一层戏剧服装**——访客来是看文章的，却被要求先接受"这是台游戏机/这是台主机"。一旦内容和壳子气质不一致，就割裂了。

于是我决定这次重设**从内容决定布局**开始，先把设计语言定下来，再倒推 IA。

## 诊断：像素 / 终端为什么感觉割裂

我把两种风格的问题摊开看：

| 维度 | 像素游戏机 | 终端 CLI |
|------|-----------|-----------|
| 视觉气质 | 复古、可爱 | 极客、效率感 |
| 阅读成本 | 高（眼睛易疲劳） | 中（要看懂"提示符"） |
| 访客门槛 | 高（要进入"游戏世界"） | 高（要懂命令行） |
| 与内容的关系 | 装饰压过内容 | 装饰压过内容 |
| 修改成本 | 改一行内容要重塑"像素" | 改一行内容要重写"提示符" |

共同的根因：**主题在"扮演"另一种媒介**，而不是让内容用自己的声音说话。这是个根本的方向错误——不是"挑哪种主题皮肤更好看"，而是"主题皮肤这个思路就不对"。

正确的解法：**个性从设计语言里来**。色彩、排版、留白、阴影、光晕、微交互——这些是承载个性的工具；而不是"把我套成另一样东西"。

## 调研：看了什么

决定抛弃"主题皮肤"思路后，我查了**"个人开发者网站还能放什么"**，确认两件事：

- **业界已有的"非博客"模块**（now 页、/uses 页面、数字花园、学习路线、工具导航、灵感仓库、个人小实验）—— 这些都**不社交**、不需要关注/点赞，但能给个人站注入深度和"正在生长"的感觉。
- **"个性"在个人站里的成熟做法**不是套个异型壳子，而是用统一的字体、配色、留白、微交互，把"这个人"自然表达出来。

我留意到几类个人站模式：
- Derek Sivers 的 "now page" 风格：一张小页面，写当前在做什么（<https://sivers.org/now/>）
- `uses.tech` 那套"我用什么"页面：编辑、终端、硬件，开发者之间爱看
- `roadmap.sh` 那种"学习路径图"：把技术栈变成可视化进度
- "数字花园"（Digital Garden）运动：比博客轻的演进式笔记，适合记录还在生长的想法
- Indie Web / 个人 Web：自己拥有内容、不依赖社交平台

这些模式都说明了一件事：**让内容呼吸，靠的是模块选择和设计语言，不是"换壳"**。

## 设计原则：个性来自设计语言，不来自主题伪装

把上面的判断压成一句话：

> **站点的"个性"是它的设计语言本身在向访客说话，不是另一层皮肤在替它说话。**

落地推论：

- 同一套令牌（色彩、字体、间距、阴影、光晕）贯穿所有板块——切换内容不切换"气质"
- 不同板块用**微弱的专属色/图标**做差异化，不是"切换主题"
- 动态感来自**微交互和克制氛围背景**（薄荷光斑、鼠标淡高光），不是"装饰视频"
- 改内容不要触发"主题重塑"——内容改动只走 token 自动跟随

## 配色落地：薄荷绿 + 天空蓝 + 阴影 + 光 + 玻璃

定了原则后，要选一个**具体可落地的配色系统**。最终拍板：**薄荷绿 + 天空蓝**为双主色，加上**阴影 4 档**和**双色光晕**（mint/sky），并决定**全站用玻璃拟态**做面（Apple-style 半透明 + 背景模糊）。

理由：
- 薄荷绿清新、有"在生长"的感觉
- 天空蓝冷静、有"信息/数据"的暗示
- 两个色既不撞，又互补：mint 给"行动"，sky 给"信息"
- 阴影 + 光晕负责"立体感 + 光亮"，让玻璃面板不浮
- 玻璃面在底层薄荷+天空氛围渐变上能呈现 Apple 系统那种"透出雾"的质感

具体令牌（双套，dark/light 各一套）：

| 变量 | dark | light |
|------|------|------|
| `--bg` | `#0F1A18`（带绿调的近黑） | `#F4FAF7`（极淡薄荷白） |
| `--surface` | `#131C1A` | `#FFFFFF` |
| `--accent`（薄荷） | `#2DBE7E` | `#18A06A` |
| `--accent-2`（天空） | `#4FA3E0` | `#2B7AD3` |
| `--shadow-1..4` | 4 档递进 + 暗色加深 | 4 档递进 + 浅色微落影 |
| `--glow-mint` / `--glow-sky` | 半透发光 | 半透发光 |
| `--glass-bg` / `--glass-bg-strong` / `--glass-border` / `--glass-inner` | 半透明 + 细描边 | 半透明 + 细描边 |

字体：
- display: Space Grotesk（现代几何，薄荷+天空气质能撑住）
- body: Noto Sans SC（中文）
- mono: JetBrains Mono（代码）

具体 hex 与所有令牌都先在仓库里以 **`docs/palette-preview.html`**（自包含的纯 HTML+CSS）落了一份预览页——通过 IDE 的 Browser 面板可以一边调色一边看深/浅两套渲染，确认 OK 之后才进入真正的 `style/tokens.css` 重写。

## 信息架构决策（IA）

按"内容决定布局"梳理。我的内容池：
- 技术 / 经验分享（已有 `/articles` + `/blog`）
- 工具分享（web/服务端/多平台；已有 `/tools` 注册表）
- 多生态学习（Java/Rust 主力；React 辅；Zig 关注；Go 生手；Cangjie+鸿蒙 早期；MoonBit 关注）

推导出的 IA（导航一级板块）：

| 板块 | 寓意 | accent |
|------|------|--------|
| `/articles` | 技术/经验分享（深度长文） | sky（信息） |
| `/tools` | 工具集（行动入口） | mint（行动） |
| `/radar` | **多生态学习雷达**（差异化） | sky（数据/可视化） |
| `/lab` | **实验/小游戏/demo** | mint（互动） |
| `/about` | 个人介绍 | 任一 |

> **学习雷达**是我最想加的差异化模块——把多生态学习进度可视化成雷达/进度图，独有、动态、跟我的学习节奏实时绑定。
> **实验室**解决"不单调"——放 Rust/Zig 写的小游戏和 demo，纯个人表达，零社交。

`/blog`（DB 表）和 `/articles`（文件）双轨统一为 **`/articles` 单一系统**，`/blog` 下线做 301 重定向，理由：双轨混乱，统一后写作流（git+CD）和后台内容（posts）职责更清楚——公众号推送走 `/articles`，随手记以后可以放到 `/radar` 或 `/lab`。

首页从"demo"改为**枢纽式**：
- 简介 + 一句话定位
- 各板块入口卡片（带板块 accent 色条 + hover 立体感 + mint/sky 边缘光）
- 最近更新流
- "在听什么"或"正在做"小条

## 玻璃质感的取舍与可读性规则

"全站玻璃"很激进。我自己担心的两个点：**(1) 文字对比度可能下降**（玻璃半透明 + 底下氛围色 → 字会糊）；**(2) 玻璃透出层要够"有戏"**（不然玻璃就没意义）。

落地规则（在记忆里写定了）：
- **可读性优先**：玻璃面板上的文字/图标必须保留 WCAG-AA 对比度。所以分两种强度：
  - **subtle glass** (`--glass-bg`)：用于卡片、头部、板块容器、列表项
  - **strong glass** (`--glass-bg-strong`)：用于悬停抬升、激活态、模态、按钮、输入框、代码块、表格
- **底层必须有戏**（已在 token 里有薄荷+天空的径向渐变氛围 + 网格 + 光斑），玻璃才能"透出雾"——否则变成"一层灰雾"
- **组件分两档**：
  - 内容/数据/输入：strong glass + 1px 实心 border + focus 光晕
  - 装饰/容器：subtle glass 即可
- 性能：现代浏览器对 `backdrop-filter` 友好；兜底加 `-webkit-backdrop-filter`

玻璃在所有地方用 ≠ 所有地方看起来一样——通过强度（subtle/strong）和边缘光晕（mint/sky/mix）三件套组合，自然分出层次。

## 沉淀与协作机制

这次的颜色/字体/阴影/光/玻璃**多参数联动**，靠文字描述不可靠。我搭了一个**自包含的预览页**（`docs/palette-preview.html`），单文件 HTML+CSS：

- 12 个色板的 hex 预览
- 阴影 4 档
- 光晕 5 种（mint/sky/strong/mix）
- 玻璃 4 种（普通/强化/mint/sky）
- 4 个板块卡片示范
- 按钮 + 链接交互

这一页的妙处：**用 IDE 的 Browser 面板直观看**。改 token → 文件保存 → 右侧 Browser 自动刷新，能在写代码的同时看视觉。这样**配色决策不再是盲改 CSS 而是"看着改"**。

落到代码层面：`style/tokens.css` 是**单源真值**——所有组件引用 token，主题切换、玻璃强弱、板块 accent 切换都自动跟随。新增组件只要把 token 嵌进去就一致。

## 下一步：站点整体重构

设计语言定了，IA 定了，玻璃规则定了。下一步是**站点整体重构**，也是这次重设的执行部分：

1. `style/tokens.css` 整体重写（薄荷+天空+阴影+光+玻璃）
2. 新增 `/radar`（学习雷达）、`/lab`（实验室）两个板块
3. 首页改为枢纽式（板块入口卡片 + 最近更新）
4. `/blog` 301 → `/articles` 统一文章系统
5. 富化模块：音乐/氛围、时钟/番茄钟
6. 全站组件按玻璃+可读性规则重做
7. CD 重打包（articles/ 下多了 radar/lab 目录吗？需评估；现阶段只新增 /radar 和 /lab 路由，文件可能用 YAML/JSON 数据 → 数据打包进 site）

这是多文件、跨页面、改路由 + 改 DB + 改 CD 的实现任务，**下一步我会进 plan mode 整体铺一遍**——把路由、组件清单、CD 打包规则都写在计划里给你过目，再写代码。

## 总结

### 核心要点

1. **割裂的根因是"主题在扮演另一种媒介"**，不是皮肤不好看
2. **个性来自设计语言**（色彩/字体/留白/阴影/光晕/微交互），不来自"换主题"
3. **薄荷+天空双主色 + 阴影 + 光 + 玻璃** 是这次选定的完整系统
4. **玻璃全站用**，但通过**强度（subtle/strong）+ 边缘光晕（mint/sky/mix）** 分出层次
5. **可读性优先**：玻璃面板上的文字必须 WCAG-AA 对比度
6. **预览页（docs/palette-preview.html）是协作面**：改 token 看着改，IDE Browser 即时反馈
7. **下一步进 plan mode** 做整体重构（IA、路由、组件、CD）
