# 文章质量门禁（公众号文章）

> 适用于 `articles/` 下的公众号文章。静态门禁由 `tools/check-articles.sh` 自动执行；内容门禁靠本清单 + 人工审核。

## 自动静态门禁（`tools/check-articles.sh`，失败即禁止提交）

1. 首行为一级标题 `# 标题`
2. 含摘要行 `> **摘要**: …`（≤200 字）
3. 含「## 参考资料」章节，且其中**不使用 Markdown 超链接**，须写「资料名称：完整URL」（避免公众号排版丢链接）
4. 含版权声明

## 内容质量清单（发布前人工 + AI 逐条核对）

### 准确性
- [ ] 技术事实准确，代码示例在本仓库真实可编译/可运行（引用仓库代码时给出文件路径）
- [ ] 版本号明确（Leptos / Axum / Rust 版本），涉及时效性表述注明写作时间
- [ ] 不臆测：无法确认的内容先查证或询问，不凭印象补全

### 深度与原创
- [ ] 有独立观点/踩坑经验，不是官方文档转述
- [ ] 讲清「为什么」，不只「怎么做」
- [ ] 有真实场景（本项目 2C2G VPS、SSR、musl 静态二进制等都是好素材）

### 结构与可读性
- [ ] 摘要 150–200 字，点明价值
- [ ] 章节逻辑连贯，标题层级不跳级
- [ ] 代码块标注语言（```rust / ```bash / ```toml）
- [ ] 公众号适配：正文不依赖外链才可理解；表格不过宽；图有替代文字说明

### 隔离原则
- [ ] 正文不暴露未公开的内部细节（服务器地址、口令、私有仓库路径）
- [ ] 截图不含 `.env`、token、个人凭据

### 发布流程
1. 初稿入 `articles/`，通过 `tools/check-articles.sh`
2. 提交人工审核，意见记入 `docs/article-reviews.md`
3. 迭代至通过审核，状态更新到 `articles/README.md`
4. 用用户指定的公众号工具排版发布；发布后记录日期与链接到 `articles/README.md`

## 与站点博客（posts）的关系

- 站点博客以 `posts`（数据库 + `/admin`）为唯一事实源（见 `.cursor/rules/rcrwhyg.mdc`）
- `articles/` 是**公众号渠道稿**，可以改写自博客文章，但两者独立维护，不强制同步
- 同一素材两边发布时，公众号版需按本规范适配排版与参考资料格式
